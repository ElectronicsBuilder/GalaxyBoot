# GalaxyBoot

Bootloader for the Galaxy board (STM32F405RG). It starts the
[BeaconGalaxy](https://github.com/ElectronicsBuilder/BeaconGalaxy)
application, or updates it from `BeaconGalaxy.bin` on the microSD card.

Part of a three-repository system: [BeaconGalaxy](https://github.com/ElectronicsBuilder/BeaconGalaxy)
(the application), **GalaxyBoot** (this one) and
[AudioGalaxy](https://github.com/ElectronicsBuilder/AudioGalaxy) (the audio
player board).

## What it does

- **Normal start:** the application starts straight away. The OLED is not
  even switched on.
- **When it updates:** when the EEPROM boot fuse is set (BeaconGalaxy's
  About › UPGRADE does this), or when ENTER is held during reset.
- **Checks before erasing anything:** the file size, the `GXIM` trailer, the
  vector table, and the CRC-32 of the whole file. A bad file is refused and
  the current application keeps running.
- **Writing:** it erases only the sectors the image needs and programs
  everything except the vector table. It checks the CRC of the flash and
  writes the vector table last. A cut-off update therefore never looks like
  a valid application.
- **The boot fuse:**
  - cleared after a successful update;
  - also cleared after a failure that left the application untouched (no
    card, no file, bad file), so a bad card cannot cause a reset loop;
  - kept after a failed flash write, so the next reset tries again.
- **Without a valid application:** shows NO APP; ENTER tries the SD card.
- **Progress and diagnostics:** progress is shown on the OLED and on USART1
  (115200). The last attempt is kept in RAM (`boot_diag`) for reading over
  SWD.
- **Watchdog (8 s):** runs during an update and in the NO APP wait. A hang
  resets the board, and the boot fuse, which is still set, makes it try
  again.

Details: [docs/memory-map.md](docs/memory-map.md).

## Build

You need STM32CubeCLT 1.16 (arm-none-eabi-gcc, CMake, Ninja) on the PATH.

```
cmake --preset Release        # Debug for the debugger
cmake --build --preset Release
```

## Flash

GalaxyBoot occupies sectors 0–5 (0x08000000–0x0803FFFF). Flashing it leaves
the application alone:

```
STM32_Programmer_CLI -c port=SWD sn=<st-link serial> mode=UR -w build/Release/GalaxyBoot.elf -v -rst
```

VS Code tasks (`.vscode/tasks.json`) cover building, flashing, the host tests
and the CI checks.

## Layout

| Folder | Contents |
|---|---|
| `App/Boot/` | our code: start-up decision (`boot_main.c`), SD update (`boot_update.c`), image checks (`image.c`), OLED text (`boot_ui.c`), jump to the application (`boot_jump.c`) |
| `common/` | code shared with BeaconGalaxy and AudioGalaxy (CRC, OLED and EEPROM drivers, boot fuse) |
| `Core/`, `Drivers/`, `FATFS/`, `Middlewares/` | generated by STM32CubeMX 6.15. Edit `GalaxyBoot.ioc` (changes are recorded in `cubemx/galaxyboot.patch`), then run `sh tools/cubemx_generate.sh .`. The SDIO clock is 8 MHz because reads are polled. |
| `tests/host/` | PC unit tests: `sh tests/host/run_tests.sh` |
